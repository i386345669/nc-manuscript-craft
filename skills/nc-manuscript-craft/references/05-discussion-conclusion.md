# 05 Discussion与结尾：把发现转化为有边界的科学解释

> 应用范围：按本轮授权、请求语言和目标期刊配置执行。下文涉及双语、文件或图形交付的步骤，仅在任务需要时启用。教学示例不构成新项目事实。

Discussion的工作是解释本研究改变了什么理解、为什么可能出现这些结果、与已有研究怎样相接，以及下一项具体检验是什么。它不应成为Results复述、文献名单或逐条自我辩护。先组织解释与证据关系，再形成正文，可减少推论跳跃。材料足够且作者要求成稿时，完成正文，不停在提纲阶段。

## 一、输入先围绕证据组织

对每项值得讨论的结果填写一张解释卡：

| 项目 | 记录内容 |
|---|---|
| 实际观察 | 对象、条件、终点、方向、必要量化及图表位置 |
| 证据身份 | 实验测量、观察关联、模型推断、计算扰动或预测归因 |
| 支持的观点 | 这一结果实际回答研究问题的哪一部分 |
| 候选解释 | 与哪些观察相容，哪些环节尚未检验 |
| 比较文献 | 具体研究对象、方法、方向及可比/不可比条件 |
| 其他解释 | 同样能产生结果的合理替代解释 |
| 后续检验 | 为区分解释，需要测量什么、比较什么、在什么对象中检验 |

只纳入对主要论证有作用的卡。不是每个显著P值都需要一段机制解释，也不是每张图都要在Discussion重述一次。先决定本研究最值得解释的推进，再组织段落。

## 二、从总体贡献到具体解释

开头用少量篇幅解释主要贡献的含义，而非照摘要重新列所有结果。资源型论文可以说明研究对象如何变得可定位、可比较或可复用。方法型论文说明研究任务现在能够怎样完成。机制型论文才以已被实验支持的机制推进为中心。

后文可以沿“分子对象—生化过程—可测问题—实际用途”深入，但这些是可选的论证层次，不要求每篇都写四段：

1. **分子或反应身份**：结果究竟定位到基因、酶、具体反应、共同变化模式还是通路标签。名称不确定时使用已核验层级，不凭相近注释直接指认酶。
2. **生化意义**：解释方向、底物/产物、反应位置或相邻过程为什么使该结果值得关注。若只有计算通量，不能用一句机制文献把它变成实测细胞过程。
3. **可测量的研究问题**：下一步不是笼统“进一步验证”，而是哪个测量能区分哪两个解释。可考虑反应相关代谢物、交换、酶活动或示踪等，但应基于具体问题，不预言这些测量会提高准确性。
4. **资源实际用途**：读者能查询、重分析、导出或在规定输入下运行什么。已实现功能与未来计划分开，不能从可查询性直接推导临床获益。

教学情境：观察性队列、计算模型与实验测量同时用于回答一个问题，但各自定义了不同终点。三者可构成互补证据，不能仅因方向相似便称为同一机制的独立验证。先核清是否测量同一对象，再决定如何连接。

## 三、机制解释按证据分层

推荐在规划阶段明确三层，正文则自然表达，不必反复贴标签：

- **已观察到的结果**：用结果本身允许的动词。模型中删除后读出变化，可写模型响应，不能省掉模型身份。
- **证据支持的解释**：指出哪些结果或已核实文献支持解释，同时交代关键条件。
- **待检验假说**：说明为何合理、还缺哪一项鉴别证据，使用与不确定性相称的限定。

“may”“suggest”“demonstrate”不是装饰性的同义词。不能一律换成弱词使全文畏缩，也不能一律换成强词增强气势。对已明确完成的操作、观察或测量，可以直述。对解释链上尚未检验的环节，限定应落在那个环节，而非给整段加一层泛泛谨慎。

示例只说明边界：

> 教学句式：Within the specified simulation, changing [input] altered [output].
>
> 若无进一步证据，不可升级为：Changing [input] improves outcomes in patients.

这些是带待填变量的合成句式。第二句添加了患者对象及实际获益，不能作为第一句的润色版本。

## 四、文献比较需要回答“如何可比”

先确定需要比较的文献类型，再检索并核实具体来源。常见比较维度包括对象、人群、条件、测量层级、模型假设、效应方向和研究终点。讨论不能只说“与某团队一致”，应说明其结果支持本文哪一层解释，以及本文新增或不同之处。

在另一研究体系完成的机制实验，可以支持候选解释，但不能替代当前体系的验证。相反结果也不必自动判为冲突，先检查测量是否同一层、是否存在条件差异。不能为了让故事整齐而虚构“首次在本癌种发现”或声称没有报道。

文章自身的原创数值来自本研究图表与源结果。外部文献解释背景与机制，不充当“本研究效应值”的来源。

## 五、具体局限，压缩重复自辩

每项局限应说明：缺少什么信息、影响哪个推论、现在仍能回答什么、哪项检验最有针对性。可用“缺失输入 → 受限推论 → 需要的测量”作为审查表，而不强迫正文三段式。

教学情境：某模型未包含随时间变化的暴露信息，可以说明它未直接刻画这一变化。该缺失本身不足以确定估计偏差的方向，也不能保证增加该变量后性能必然提高。具体判断须依据模型、数据与比较证据。

避免在每段末尾重复“不是因果”“需要进一步研究”。必要边界在相关推论处说清，完整实现细节到Methods/SI，重复审计和纠错过程留项目记录。对会改变核心解读的限制，不以“去防御写作”为理由删掉。

若局限只剩泛词，如样本有限、需要临床验证、需进一步实验，逐项追问：哪类样本不足，哪个终点，何种测量能解决哪个解释。这比堆更多谨慎词更有效。

## 六、结尾与独立Conclusion

是否单设Conclusion由文章类型和作者稿件决定，不能为了套模板额外添加。Discussion末段通常可完成收束：本研究支持的主要增量、可用方式和最具体的下一问题。

结尾不要再列一次全部Results，也不制造“开启新时代”的远景。只在证据支持时给直接研究意义。若是资源论文，可回到它使什么研究对象可被查询和复用。若是发现论文，可回到它改变了哪一认识。承诺未来用途与已经实现的用途分别写。

## 七、完整可复制prompt

### P05-A：从关键结果提取讨论路线

```text
我正在撰写Discussion。请根据以下材料先设计论证，不直接堆文献或重复Results。
研究问题：{{问题}}
核心贡献：{{贡献}}
关键结果卡，含对象/条件/图表/方向/证据类型：{{结果卡}}
已核实文献及支持范围：{{文献}}
作者希望讨论的判断：{{作者判断}}

逐项说明结果支持什么观点、可能解释、可比较文献维度、替代解释及当前限制。
把需要后续证据的解释明确标出，不添加数据或机制。
随后给段落路线，每段说明目的和怎样接到下一问题。
按论证需要安排，不要求每段重复同一套五步结构。
```

### P05-B：机制与文献比较专项

```text
请审查以下Discussion中的机制解释和文献比较。
草稿：{{草稿}}
本研究实际证据：{{数据与图表}}
文献原文或已核实片段：{{来源}}

区分直接观察、证据支持的解释和待验证假说。
每个机制说明对应哪些观察、引用支持哪一环以及哪个环节仍未检验。
比较具体对象、条件、测量层级和终点，不能只写“与已有研究一致”。
发现关联升格因果、别的癌种机制转移、本研究数值引用外部论文等问题时，给最小修订。
未知的新颖性或未检索领域保持未知，不推断“首次”或“尚无报道”。
```

### P05-C：具体化局限并去除重复防御

```text
请在保留证据边界的前提下修订以下局限和重复自辩。
文本：{{文本}}
实际输入、设计和测量范围：{{范围}}
必要条件与已完成检查：{{条件}}

每项局限说明缺失信息影响哪个推论，以及哪项具体测量或比较可以区分关键解释。
不推测未证明的误差方向，不保证补充数据必然改善模型，不捏造已做或最初计划。
删除重复的预防性句子，把详细实现诊断放入明确的Methods/SI位置，但保留改变核心理解的条件。
输出修订稿和“保留/合并/移位/删除—理由—证据是否仍在”的表。
```

### P05-D：形成Discussion成稿与结尾

```text
请依据已确认路线完成Discussion。
路线与贡献层级：{{路线}}
已核实结果及引用：{{证据}}
需要保持的作者判断和术语：{{作者声音}}
具体局限与可检验问题：{{边界}}
篇幅与是否单设Conclusion：{{篇幅配置}}

用结果的含义组织段落，按需要连接分子/反应身份、生化解释、可测问题和资源实际用途。
不逐项重述Results，不将不同外部测量写成同一验证链，不增加新机制、首创或未测收益。
长短句和段落详略由论证内容决定，不强行统一或随机打散。
结尾回到已支持贡献和具体下一问题，避免笼统宏大展望。
输出成稿和少量关键取舍说明，并检查所有引用与其主张匹配。
```

## 八、验收清单

- [ ] 开头解释贡献，不复述全部结果。
- [ ] 机制各环节与观察、文献或理论支持对应。
- [ ] 相关、模型扰动、实验和预测归因身份保持。
- [ ] 文献比较说明对象与条件，未借用他人验证替本研究背书。
- [ ] 局限具体到推论与测量，未猜误差方向或收益。
- [ ] 不反复自辩，必要边界仍在读者可见位置。
- [ ] 结尾既没有全盘保留套话，也没有新增夸大意义。
- [ ] 是否独立Conclusion符合实际稿件结构。
