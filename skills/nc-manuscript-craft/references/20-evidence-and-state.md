# 20 证据映射、变更依赖与断点恢复

## 何时使用

用于材料来自多个文件、主补图需要重排、多语言或多版本并行、任务跨多个工作批次的情境。只改一句语法时，核对该句及上下文即可，不必建立整套表。

本模块用于后台定位、同步和续接科学内容。论文正文正向呈现实际研究，证据状态、核查过程和待确认事项存于工作记录或简短作者说明。本模块不要求重跑原分析，也不把已完成的作者决定重新变成阻塞。

## 1. 最小证据映射

稳定ID标识科学内容，不依赖当前段落序号或Figure编号。可沿用项目已有ID，无需另造一套。新项目可用R001代表结果、M001代表方法、F001代表整组图、C001代表引用命题、Q001代表待确认事项。

这些ID通常只用于工作记录，不应全部出现在论文里。一个图可支持多条结果，一个结果也可由多个图表共同支持。

使用[证据表模板](../assets/evidence-ledger.csv)时，按实际需要填写：

| 字段组 | 实际记录内容 |
|---|---|
| 身份 | 稳定ID、结果或主张、研究分支与证据类型 |
| 对象 | 人群/体系、独立单位、纳入或合格集合、时间、条件及处理阶段 |
| 比较 | 暴露/处理/预测对象、参照组、终点和效应尺度 |
| 结果 | 已报告的估计量、不确定性、必要n及统计身份；比例的分子、分母和源字段 |
| 来源 | 当前文件/表/单元格/图/原文位置、版本或可核对日期 |
| 方法 | 产生该结果的真实方法与统计定义位置，必要时定位执行版本、配置和保存输出 |
| 呈现 | 整组图、面板、表格、正文/SI句段及双语对应 |
| 引用 | 外部引用支持哪个命题，或实际数据/方法出处 |
| 状态 | 已核对、作者提供、部分待核、来源冲突、已被取代等 |

只记录会影响写作的事实，不复制整个原始数据库。没有必要的字段可空置并标不适用，不能为表格完整猜填。

### 来源状态不混同

- **已对照来源**：本次实际查看了所需内容，记录定位。
- **作者提供**：依据当前作者资料写作，未声称另行独立认证。
- **待核实**：来源存在或被提及，但关键内容未读或不足。
- **来源冲突**：有不一致，尚未确定是否不同对象或错误。
- **已被取代**：保留历史，不再供当前成稿引用。

来源被作者确认存在，不等于所有数字、许可或机制也被确认。与此同时，旧审计中的pending不能覆盖作者随后确认的新状态。遵循当前有效资料与明确范围。

复杂计数还需区分患者、样本、记录、特征、映射及检验单元，以及筛选前后使用的字段空间。某面板的记录数与另一面板的合格患者数可以都正确。百分比须保留其真实分母，不能为全文看似统一而改成同一个n。技术重复和嵌套人群也不能累计为新的独立对象。

## 2. 从结果向两边核查

向方法回查：这个估计量是否有计算对象、比较、尺度、缺失处理、校正家族与不确定性定义。向文字与图表回查：读者看到的句子、坐标轴、图注、脚注和摘要是否都指向同一对象。

至少留意以下断裂：

- 正文主张没有结果或来源支持。
- 图注n与方法n看似不同，但未说明纳入、合格、成功或配对集合。
- 同名评分、模型版本或不同队列被合并成同一验证。
- 方法保留旧流程，结果已来自另一个流程。
- 图号正确，所引用面板却属于另一个科学对象。
- 外部机制文献被移到本研究效应句后，像是在提供本研究数据。
- 文献库存在条目，但正文从未使用。反之，正文标记缺对应条目。

发现差异时先判断是否合理的集合、时间或尺度区别。不能见数字不同就统一，也不能见术语相同就认定相同。

### 方法缺口的执行来源

若任务需要补齐已经完成研究的方法，优先查产生现有结果的实验记录、脚本版本、配置和保存输出。仅看到一个工具函数不足以证明实际使用了它，需追踪相关调用和结果身份。按缺口核定输入资格、候选范围、优化目标、并列与缺失处理、重复汇总、评价集合或派生分类的完整条件。无需为一个缺口读取全部代码库。

将核定规则转为读者能复现的方法文字，技术定位保留在工作记录。条件很长时由Methods承担，图注给必要定义与入口。不要把默认参数、领域惯例或备用分支误写成实际执行方法，也不要为完善文字重新选择阈值、训练模型或改变分类。

对已保存结果做必要算术一致性核对，可用于确认报告来源，但应与重拟合或新统计推断区分。无法核定时说明哪项规则未知，继续不依赖它的写作。不可评估、缺失、未执行与未达到条件分别报告，不能猜测一个类别未通过的具体原因。

## 3. 稳定科学ID与可变显示编号

图表移动时，保持F001等身份不变，只更新当前显示编号。维护简短的“稳定ID—旧编号—新编号—受影响引用”映射。

同步检查正文、摘要中的图指针、完整图注、SI、表注、双语版本、独立图注源与图合集目录。只有本轮实际存在且受影响的副本才需要同步，不能为清单齐全新造文件。

完整图的身份还包括其面板集合。每Figure一页的阅读合集要核对全部panel，而不只核对总页数与书签。

内部源键与可见显示名可不同。简化长键时保留稳定身份及必要条件，记录可逆映射，不改源表来适应排版。完整核对版、投稿尺寸版与continued页面可共享同一科学ID，分别维护页码和引用位置。

## 4. 源内容改变后的影响范围

把变更分为三种。

**纯表达变更**：语法、主语、标点或必要压缩。检查语义、引文、双语和版面等直接接口，不重新计算统计。

**显示与组织变更**：图表编号、段落拆合、正文/SI移位、已授权的参数显示精度。更新相关指针和精确值位置，核对拆分后的条件与引用。

**事实来源变更**：结果值、样本资格、分析定义、方法版本、比较对象、数据公开状态或作者科学决定发生更新。识别使用该来源的结果与主张，再检查它们在结果、方法、摘要、讨论、图注、表格、SI和投稿信中的实际依赖。

旧检查结论只对原版本有效。源变更后，把受影响项目暂记为“需要重核”，其余已通过部分保留。图、图注、正文或最终合成文件任一更新，都应更新对应清单和实际依赖，不能只刷新文件名。不得未经检查继承通过状态，也不要因为一个数值变化重写所有无关段落。对完全相同的继承内容可记录字节或像素身份作为复用依据。

保留变更前版本、当前来源和取代关系。不能选择更阳性的结果或更顺口的叙述作为新权威版本。作者已明确指定当前事实基线时，在该范围内执行。

## 5. 保存可恢复的项目状态

复杂任务可使用[项目状态模板](../assets/project-state.yaml)。文件内容简短、真实、能定位实际成果即可。建议包含：

1. 当前任务与作者要求，包括语言、输出形式、修改范围和保护项。
2. 当前源文件与版本，以及可核对的身份。需要严格冻结时用哈希，普通段落任务不强求。
3. 中心问题、贡献和研究类型的当前决定。
4. 已完成、处理中、待完成组件及其实际文件位置。
5. 稳定科学ID、编号、术语、引用状态及相关映射位置。
6. 待确认事项、影响范围、需要的事实和目前负责人。
7. 实际完成的检查、适用版本、仍未做的检查。
8. 下一项具体操作，而不是笼统“继续优化”。

状态文件不能只写“Results已完成”，却没有正文保存位置。也不能把拟执行检查写进已完成列表。文件不存在或工具不可用时，可在对话中交付同样结构的续接说明，让作者能复制到下一个上下文。

## 6. 续接动作

继续任务时先读最新状态与当前作者新消息，再确认实际文件和版本。不要先从最旧历史重新推理一遍中心问题。

- 文件与状态一致：从下一操作继续，沿用已通过内容。
- 新消息扩大或缩小范围：更新决定与交付矩阵，只覆盖其明确范围。
- 文件有新改动：比较实际差异，确定哪些来源或段落需要重核。
- 状态与文件不一致：报告具体差异，优先保护作者最新修改。不能静默覆盖。
- 上一批只完成部分：保持部分完成状态，继续补齐剩余范围，不将本批结束称全稿完成。

如果输入缺口暂时未得到回答，可继续不依赖它的任务，但不能把等待时间视为作者确认。能通过材料核实的问题直接核实，不重复询问已知信息。

## 7. 完成矩阵

[交付矩阵](../assets/deliverable-matrix.csv)的一行代表一个实际需要的组件，例如主稿、某语言版本、SI、参考表或图合集。可把大组件按稳定章节ID拆成子项。文件较多时增加用途与内容范围，区分编辑源、工作核对、外部评阅及正式上传材料，不能因名称相近而合并身份。上传映射见[模块17](17-submission-package.md)。

建议状态使用`not_started`、`drafted`、`awaiting_input`、`needs_recheck`、`checked`、`delivered`或`not_requested`。`checked`须写明检查内容与对应版本，不能代替整套项目通过。

交付前检查每项是否有实际内容和可用位置，是否与当前来源一致，是否仍有关键查询，哪些格式核验没有完成。区分指令执行、科学内容核对、实际视觉检查、资源访问和投稿资料状态。最终说明由这张矩阵的实际状态汇总，不以文件数量或一个笼统“完成”代替。

## 可复制指令：恢复与依赖更新

```text
请读取当前项目状态和实际文件，接续已经授权的论文工作。
保持当前作者决定、科学对象、术语、引用与已通过段落。先核对状态对应的文件版本，再从记录的下一操作继续。

若来源或作者决定更新，找出其直接依赖的结果、方法、图表、摘要、讨论与附件，只重查受影响部分。不要恢复旧版撤回的内容，也不要重新改写所有已通过段落。

缺少事实时保留稳定查询与影响范围，继续独立可完成内容。每批结束保存实际成果位置、完成范围、未决项、做过的检查和下一操作。交付状态必须与真实文件和内容一致。
【当前状态、文件、最新作者决定】
```
