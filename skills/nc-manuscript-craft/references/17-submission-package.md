# 17 投稿信、声明与投稿文件

> 应用范围：按本轮授权、请求语言和目标期刊配置执行。下文涉及双语、文件或图形交付的步骤，仅在任务需要时启用。教学示例不构成新项目事实。

## 任务边界

本模块用于从当前定稿生成投稿信、贡献概述、已请求的声明及投稿文件清单。先确认完整期刊名和文章类型。缩写可能指向不同刊物，使用完整刊名避免误解。格式、必需声明及上传类别按本次可核查的官方指南和提交系统处理。记录访问日期及文件自身修订日期，不把旧文件的近期访问日称为新政策。仅写投稿信时，不扩大为全套文件重排。

## 1. 投稿信的核心工作

投稿信让编辑快速判断：研究解决什么问题，最有依据的新增贡献是什么，证据为何支持它，以及为何适合该期刊读者。信件和其他读者说明采用与正文一致的正向论证，直接呈现研究价值与真实交付状态；不预演质疑、自辩或重复免责声明，也不复制摘要清单、罗列分析和文件数量。核查过程及待作者确认的事项另放简短工作说明。

可采用的组织：提出稿件和文章类型 → 科学问题及中心贡献 → 少量决定性证据与具体用途 → 期刊读者相关性 → 必需声明。这个次序是可调整的，不要求固定段数。

与摘要相比，投稿信可以更直接解释文章定位与读者价值，使用与正文相同的证据强度。例如方法、发现或资源实际改变了哪些研究选择，可以说明研究者据此能够开展什么工作。经费节省、使用门槛或实践收益等具体主张，应由相应评价支持。

对方法与前人关系说清新增部分，不靠弱化直接先例或未核查first-ever制造新颖性。拟投高影响力期刊也不需要夸张形容词。

## 2. 与正文同步核验

至少核对标题、研究对象与来源、主要计数、核心比较或推理、结果强度、相关资源的可用状态、稿件版本和作者名单。正文更新后，投稿信内旧数据不能遗留。少数正文没有写入的材料可以作为投稿声明，但必须是真实、被授权且适合给编辑的信息。

语言更有力不等于有新证据。投稿信不新增机制确证、外部验证、优先权、临床效益或未实现的公开入口。

## 3. 声明需要真实资料

数据与代码可用性要区分：正式公开、审稿期访问、受限访问、按申请提供、尚待存档。提供实际库名、版本、URL/DOI或受限获取途径。不得把“已有本地文件”自动写成“公开可下载”。

作者贡献、伦理审批、患者同意、资金、利益冲突、原创性、所有作者同意投稿、预印本和相关稿件等，从作者资料和当前项目状态填写。缺少信息标明待填，不能用常见模板猜测。“No competing interests”也是事实声明，不能默认。

AI辅助使用说明按实际工作范围和当前适用政策核对。不要为了文字更像人而删除已有真实披露，也不要在没有核查时宣布整套稿件已经完全合规。

投稿、公开上传或联系编辑需要相应明确授权。完成本地投稿材料不等于已经投稿。

## 4. 从工作材料到实际上传文件

用户问“应该上传哪些文件”时，先核对现有文件实际包含什么，再映射当前提交要求。文件名含Supplementary不代表已经包含所有补图；可编辑正文、含图整合PDF和完整图核对册可能承担不同任务。

| 用途 | 选取原则 |
|---|---|
| 完整工作包 | 用于继续编辑和恢复版本，可含源文件、清稿、修订稿、对应语言版本及核查记录 |
| 外部评阅包 | 提供本轮需要评阅的同一版本及必要支持材料，避免重复副本与无关内部记录 |
| 期刊上传材料 | 仅按当前文章类型和系统类别选择正式稿、图件、SI及要求的声明、数据或其他附件 |

不要把工作包或外部评阅ZIP默认当作期刊上传包，也不把中文对照、tracked稿、审计记录、完整图核对册全部默认上传。修订投稿需要哪些带修订文件，以本次要求为准。逐图文件、合并图册、SI文件和图形摘要的接受方式可能不同，不能从别人的投稿包推定。

按任务规模给出简短上传映射：具体文件、版本/语言、实际内容、上传类别、必需或可选、与其他文件的重复关系，以及尚待填写的信息。需要严格冻结时记录哈希。图形摘要可以只作为作者展示素材保存，不因已有素材就加入正式主稿，具体处理见[模块07](07-figures-legends.md)。完整Figure核对册也不自动替代投稿尺寸图件。

本地稿件完成与审稿访问可用分别报告。Data/Code availability所指的版本、入口和获取方式应真实存在；manifest或本地文件名本身不是可访问链接。未知作者信息、声明或访问地址按作者当前状态保留待填，不编造，也不阻止不依赖这些资料的文件整理。只读咨询直接给文件用途与选择，不自动执行打包、外发或投稿。

## 可复制 prompts

### P17-A 投稿信

```text
请基于当前最终稿撰写投稿信，目标期刊为【完整名称】，文章类型为【类型】。
先提炼科学问题、核心新增贡献、最有依据的支持和对该刊读者的具体价值，再写简洁连贯的信。
不要复制摘要清单，不新增首创、临床获益、用户门槛、公开访问或量化节省的承诺。
标题、计数、证据强度、资源状态与正文一致。必要声明只使用我给出的事实，未知项目单独列出待填。
输出【语言/是否双语/文件格式】，仅生成材料，不投稿或发送。
【最终稿】
【作者与声明资料】
```

### P17-B 稿件—投稿信回归

```text
请对照最新正文和投稿信，检查研究问题、贡献层级、结果对象、主要计数、证据强度及资源可用性是否一致。
标出投稿信比正文更强、使用旧版数字或新增未经核查承诺的位置，并做最小必要修复。
保留真实期刊适配理由。不要把一般的期刊偏好写成录用保证。
【正文/投稿信/本轮更新】
```

### P17-C 声明整理

```text
请根据以下已提供资料整理所需的数据、代码、伦理、作者贡献、资金、利益冲突及AI辅助声明。
将有事实依据的内容写成可用声明；已核实、作者提供、待确认和不适用等工作状态放在独立作者说明中。编号、链接、许可、同意及利益冲突使用作者提供或可核实的事实。
精确要求按本次目标期刊官方指南核对并注明日期。不要执行上传、公开或发送。
【期刊/文章类型/真实资料/所需声明】
```

### P17-D 实际上传文件映射

```text
请核对目标期刊、文章类型及当前提交要求，并检查现有交付文件的实际内容，整理应使用的上传文件清单。
区分完整工作包、外部评阅包和正式投稿材料。逐项列具体文件、版本/语言、包含内容、上传类别、必需或可选及重复关系。
特别辨认可编辑SI正文是否含图、整合SI是否完整、主图是否有合适的独立文件，以及图形摘要是否属于本次投稿材料。
不要只凭文件名或旧范例判断，不默认上传全部中间文件，不编造缺失声明或访问入口。
记录当前要求的来源与日期，准确说明待填信息和未核查范围。只整理清单，不执行上传、公开或发送。
【期刊/文章类型/初投或修回/当前文件/已知系统要求】
```
