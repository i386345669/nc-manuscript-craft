# 01｜论证主线、研究定位与修改范围

本模块用于确定文章要让读者记住什么，以及每部分为何存在。它适用于初稿规划、结构失衡的重构和成熟稿局部诊断。不要因为调用本模块，就把已定稿论文推回“从头设计课题”的阶段。

## 章节职能与完成标准

从使用者提出的科学问题出发，结合研究方向、已有结果和材料，选择本文能够回答的具体研究问题与切入点。问题尚宽泛时，可协助提出有材料依据的切入点及其区别；已有信息足够时直接组织写作。一条可用主线应说明具体问题、关键证据、主要贡献，以及结果增加了什么认识。方法、资源、生物学案例、临床关联和工具应用可以共存，但不能各自争夺同一个“核心创新”的位置。

完成标准不是一句漂亮口号。作者应能用自己的话回答：我们具体交付了什么，哪两三项结果使它值得发表，哪些模块支撑中心，哪些只是展示用途。标题、摘要、引言的问题和Discussion的解释应指向同一贡献。若文章已经做到这些，本模块只检查新增改动是否破坏一致性。

## 开始前的输入

从零起草时，输入可以是作者的口述稿、逻辑框架、项目文件与结果来源，协助梳理其中的科学问题并选择具体切入点。润色、局部修改或重构时，当前正文或目标段落及必要上下文是必需基线，先读取现稿并保留作者已形成的内容，再核对完成本轮修改所需的来源。

将材料分为四类：已经完成的事实、研究计划、外部评论和叙事范例。一个被粘贴进对话的审稿建议仍是建议。假设实验成功的示范稿也不是结果库。记录作者明确接受、拒绝或后来覆盖的选择，尤其注意图数、章节数、命名和分析范围的变化。

可以建立简短的论证表，不必复制整个实验审计系统：

| 字段 | 应记录的内容 |
|---|---|
| 对象 | 实际测量或计算的是什么，适用人群与版本是什么 |
| 发现 | 结果支持的观察或比较，包含必要范围 |
| 证据 | 图、表、分析记录或原文位置 |
| 作用 | 定义资源、评价方法、回答生物学问题或展示用途 |
| 边界 | 哪种常见解释会把这项结果说过头 |
| 状态 | 已完成、建议、待核验、已被后续版本覆盖 |

## 实际推理与编辑步骤

### 1. 先决定此次需要动多大

区分三个层级。**文字层**只改节奏、主语和措辞。**段落层**调整发现、设计与解释的顺序。**全篇层**才改变中心、章节和主图。若作者赞同当前架构，仅指出分号多或图注机械，应在文字层处理，不能借机重做整个故事。

对成熟稿先写一份保护清单，包括已确认的中心、结果对象、数据、图号、关键术语、统计定义和引用。把真实发现与技术过程分开，但不要以“突出贡献”为名删除必要定义或影响结论的相反结果。

比较两个成熟版本时，分别判断事实密度、解释是否充分、贡献表达、衔接与收束。以当前稿为基线，保留已经改善的部分，再局部采用另一版中仍获作者接受、仍有证据支持的表达。较新、较短或改动较多，都不能单独作为选择整版的理由。

### 2. 用证据选择中心，不用目标期刊倒推结论

候选定位可以包括方法改进、可复用资源、机制研究和临床应用。逐项问：最强证据实际检验了哪一个定位，是否有充分对照，其他模块提供的是同一对象的验证还是不同用途。

不要只凭规模、网页或显著结果数量认定贡献。资源文章更有说服力的表述是用户能完成何种以前不便完成的研究判断。方法文章需要说明具体比较任务与增量，机制文章需要相应的因果或干预证据。模型扰动和临床相关都可能有价值，却不自动等同机制证明。

### 3. 写出“贡献句”和“证据句”

贡献句说明本文回答的具体问题及实际推进，证据句说明支持这一判断的关键结果。可按材料写成“本文在[对象与条件]下考察[问题]，由[关键证据]支持[发现或贡献]”。两句使用一致的研究对象和证据关系，具体结构随文章内容安排。

若不同分析用不同评分、不同人群或不同测量，要写成平行应用。不要为了让故事连贯，将它们改称一个签名的连续验证。数字、成员与量纲不一致时先核对定义，不靠语言糊合。

### 4. 画出章节职责，不把职责强制变成格式

每节用一句话说明它给读者增加什么认识。常见关系包括先定义对象再进行比较、由整体观察进入具体实例、由已发现关系提出进一步检验，或并列说明互补证据。章节衔接按实际论证关系展开。

一节若仅重复另一节的结论，考虑合并或下沉细节。一节若提供独立用途，可以保留自己的逻辑，不要求硬接成机制链。章节篇幅按论证责任分配，避免均匀分成相同长度的“目的—方法—结果—总结”。

### 5. 把质量保证放到合适的位置

研究对象、数据来源、方法版本和统计定义共同支持结果的可理解性。正文保留解释发现所需的内容，复现细节进入Methods或补充材料，文件校验与编辑历程进入工作记录。

### 6. 对照作者与后续版本决定

外部评估可能建议删掉某章，作者后来明确恢复。后者是结构上的有效决定，仍需按实际证据调整措辞。不要在后续润色中偷偷恢复早期外部建议。章节数、图数、研究体系和展示范围均由当前证据与作者决定，不预设固定配额。

## 常见失败与修法

| 失败 | 修法 |
|---|---|
| 文章像完成事项清单 | 找出每项工作产生的观察，再按读者理解的依赖关系组织 |
| 所有模块都叫创新或验证 | 区分中心贡献、支撑证据、不同对象的应用和技术基础 |
| 借用范例的成功叙事 | 保留其提问方式，用本稿真实结果重写结论，删除未执行完成式 |
| 为避免防御而抹掉定义 | 用准确名词和范围表达边界，减少重复道歉，不降低透明度 |
| 过度强调“可追溯、可复用、全面” | 改成用户具体可以查询、比较、重算或解释的动作 |
| 成熟稿一个小问题引发全篇重建 | 返回本轮范围，局部修订并检查受影响的相邻文本 |

## 审查点

- 中心主张是否由当前结果支撑，而非未来方案或期刊期望支撑。
- 标题、摘要、引言和Discussion是否使用同一对象与贡献定义。
- 各模块之间是否有真实逻辑关系，是否出现“不同对象接成同一验证链”。
- 正文贡献是否足够清楚，质量控制是否有适当位置而非被删除。
- 是否尊重作者最新明确决定，没有继承过时版本约束。
- 是否说明修改范围与必要性，没有把局部润色变成额外研究任务。

## 可直接复制的 prompts

### P01-A｜从材料建立主张与章节职责

> 请根据我提供的当前稿件、主要图表和结果来源，先判断本文实际交付的中心贡献。把已完成事实、研究计划、外部评论与写作范例分开，不把范例中的成功结论移植给本文。输出一张简短论证表，列研究对象、主要发现、证据定位、适用范围和该结果在全文中的作用。随后提出一个首选中心主张与最多两个较窄备选，并说明每个版本需要哪些现有证据。最后用一句话说明各章节给读者增加什么认识，标记重复、断裂与可下沉细节。不要改动数字、统计定义、引用或评分身份，不预设所有章节必须连成单一机制链，也不承诺目标期刊接收。

### P01-B｜成熟稿的最小结构修订

> 当前稿件的中心与整体架构已经得到作者认可。本轮只处理这些问题：[列出问题]。先列必须保护的研究对象、主要结论、章节、图号、术语与引用，再判断哪些问题只需文字调整，哪些确需段落内重排。默认采用最小修改，不重启课题设计、不增加新验证、不恢复旧版已经撤销的分析。对每项建议给出修改前后及其改善的具体阅读问题。若发现影响事实正确性的矛盾，单独标出来源与影响范围，不用静默重写掩盖。

### P01-C｜消除审计报告式叙事

> 请检查下文是否过多围绕文件、版本、检查和完成步骤展开。对每段先说明它目前承担的功能，再找出作者真正得到的观察或新增研究能力。保留理解结果必需的对象定义，把不必占据正文的工程细节建议移到Methods、补充或发行说明，并给出明确去处。改写时让研究对象、关键变量、比较结果或实际研究任务成为合适的主语。不要机械规定每段结论先行，不给每段补统一小结，也不要把有用的质量控制当作冗余删除。输出修订文本与简短的段落职责对照。
